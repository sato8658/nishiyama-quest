# NISHIYAMA QUEST 試作版

「今日の西山公園を、あなただけの冒険に。」をテーマにした、スマートフォン優先の観光クエストWebアプリです。

## 起動方法

Node.js 22.13以上を用意し、プロジェクト直下で `npm install`、続いて `npm run dev` を実行します。表示されたローカルURLを開いてください。本番確認は `npm run build` で行います。pnpmを使用する場合は、それぞれ `pnpm install`、`pnpm dev`、`pnpm build` に読み替えられます。

## 主な構成

- `app/page.tsx` 画面と操作フロー
- `app/globals.css` モバイル優先デザイン
- `lib/route-engine.ts` UIから独立したルールベースのルート生成
- `lib/data-loader.ts` 実データ列名・座標の正規化
- `data/` 鯖江市オープンデータ原本とアプリ読込用JSON
- `data/red-panda-source/` レッサーパンダ画像オープンデータの原本ZIP・展開画像・CKANメタデータ
- `public/red-pandas/` クエスト画面で使用する公式代表写真と、写真未準備個体用の共通プレースホルダー
- `lib/red-panda-images.ts` 個体名・代表画像・公式データセットURL・提供元・ライセンスの対応表
- `scripts/build_open_data.py` CSV/XLSXから読込用JSONを再生成

将来AI APIを導入する場合は、`generateRoute` と同じ入出力を持つ別実装へ差し替えます。

## 使用データ

指定された6データセットの実ファイルを収録し、アプリ内の「使用オープンデータ」画面に件数、用途、「提供：福井県鯖江市」、CC BY 2.1を表示します。取得元と用途は`OPEN_DATA_SOURCES.md`に記録しています。

## データの差し替え方法

1. `data/README.md` を確認します。
2. 鯖江市から取得したCSV/XLSXを対応する同名ファイルへ差し替えます。
3. Shift_JISのCSVはUTF-8へ変換します。
4. `scripts/build_open_data.py`を実行して`data/open-data.raw.json`を再生成します。
5. 原本の列名が変わった場合は`lib/data-loader.ts`の別名定義を調整します。

個体名、プロフィール、施設名、座標はオープンデータに存在する値だけを使用してください。

## デモモード

クエスト画面から「現在地を確認」を開き、デモモードをONにするとGPS到着判定だけをスキップできます。ルート地点、個体名、プロフィールはデモモードでも実データのままです。架空地点は使用しません。

## 称号履歴の端末内保存

COMPLETE時に獲得した称号をブラウザの`localStorage`へ保存します。ログインやサーバー送信は行いません。同じ称号を複数回獲得しても重複登録せず、最初に獲得した日付を保持します。冒険カード画像は保存しません。進行中のポイントやクエスト状況は、下記の別キーへ保存します。

- 保存キー：`nishiyamaQuest.earnedTitles.v1`
- 保存形式：JSON配列
- 各要素：`{"title":"西山公園冒険家","firstEarnedAt":"ISO 8601形式の日時"}`

保存データ例：

```json
[
  {
    "title": "西山公園冒険家",
    "firstEarnedAt": "2026-08-30T03:00:00.000Z"
  }
]
```

ブラウザ設定などで`localStorage`が使用できない場合も、アプリとCOMPLETE画面はそのまま動作します。その場合、称号履歴はページ再読み込み後には保持されません。

## 冒険の進行状況の端末内保存

生成済みの冒険が進行中の場合、ブラウザの`localStorage`へ自動保存します。TOPの「冒険のつづきから」から、最後に進めていたクエストを再開できます。COMPLETE時には進行状況の保存データを削除し、称号履歴だけを残します。

- 保存キー：`nishiyamaQuest.adventureProgress.v1`
- 保存対象：現在のクエスト番号、完了済みクエストID、ポイント、交通手段、同行者、滞在時間、興味、生成ルートの地点IDと順序、今回見つけたレッサーパンダ名、現在の称号候補、更新日時
- 保存しないもの：GPS現在地、デモモード、冒険カード画像

保存データは次の構造です。

```json
{
  "version": 1,
  "status": "active",
  "currentQuest": 1,
  "completedQuestIds": ["park-1"],
  "points": 100,
  "transport": "車",
  "companion": "家族",
  "duration": "90分",
  "interests": ["自然", "散策"],
  "routeIds": ["park-1", "park-2"],
  "foundRedPandas": ["かんた", "ライト"],
  "titleCandidate": "西山公園ビギナー",
  "updatedAt": "ISO 8601形式の日時"
}
```

「新しい冒険を始める」を選んだ場合は確認画面を表示し、了承後に進行中データだけをリセットします。獲得済み称号は削除しません。`localStorage`を利用できない環境でもアプリは動作しますが、再読み込み後の進捗復元はできません。

レッサーパンダに興味を選んだ場合、ルートには個体名ではなく「レッサーパンダ観察QUEST」を1件だけ生成します。クエスト内には「西山動物園のレッサーパンダ一覧」と公式写真登録の対象個体を件数固定せず全件表示します。公式写真が未準備の個体にも共通の「写真準備中」画像を表示し、今日会えた個体を複数記録できます。1頭以上を発見して任意にクエストを終了すると100 POINTを1回だけ付与します。

## 本番化する場合の追加作業

- 6データセットの正式ファイル、列対応、文字コード、ライセンスの確認
- XLSXパーサーと定期データ更新処理の追加
- 実座標に基づくOpenStreetMap表示と経路計算
- GPS到着距離、誤差、位置情報同意UIの現地検証
- 公共トイレ、駐車場、バス停の近距離検索を正式データへ接続
- アクセシビリティ、端末・ブラウザ、通信断、負荷、セキュリティの試験
- 利用規約、プライバシーポリシー、問い合わせ先、分析同意の整備
- AI APIを使う場合の鍵管理、送信データ最小化、フォールバック実装

冒険カードはブラウザのCanvas APIでPNGとして保存します。外部有料サービスや外部送信は使用していません。

## Vercel公開方法

このアプリは、APIキーや環境変数を設定せずにVercelへ公開できます。オープンデータはビルド時にアプリへ含まれ、公開後も利用者によるファイル選択は不要です。

1. GitHubで新しい公開用リポジトリを作成し、このプロジェクトのファイルをアップロードします。`node_modules`、`.next`、`.env`、`.env.local`、参考画像ZIP、作業用画像フォルダはアップロードしません。アプリが使用する画像は`public/assets`に入っているため、こちらは必ずアップロードします。
2. [Vercel](https://vercel.com/)へログインします。
3. 「Add New」から「Project」を選び、GitHubのNISHIYAMA QUESTリポジトリを選択します。
4. Framework Presetが「Next.js」、Build Commandが `npm run build` になっていることを確認します。環境変数は追加せず、そのまま「Deploy」を押します。
5. デプロイ完了後に表示される `https://...vercel.app` のURLを、スマートフォンのSafariまたはChromeで開いて動作を確認します。

応募用URLはVercelの公開URLを使用します。Vercel AuthenticationやPassword Protectionは有効にせず、URLを知っている人がログインなしで閲覧できる設定にしてください。

### 公開後の確認項目

- TOPからCOMPLETEまで画面遷移できること
- 画像が表示されること
- 「使用オープンデータ」に6データセットと読込件数が表示されること
- 位置情報を許可した場合に現在地を取得できること
- 位置情報を拒否しても画面が壊れず、デモモードを使用できること
- 冒険カードを画像保存できること
